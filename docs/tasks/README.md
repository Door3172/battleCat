# 任務系統說明

每個角色一個任務檔：

| 檔案 | 角色 | ID 前綴 |
|---|---|---|
| `ceo.md` | 專案執行長（CEO）——決策請求、歸屬不明的問題 | `CEO-` |
| `ui.md` | UI / 美術 | `UI-` |
| `allies.md` | 友軍（貓咪） | `AL-` |
| `enemies.md` | 敵人 | `EN-` |
| `levels.md` | 關卡 | `LV-` |
| `economy.md` | 經濟 / 數值平衡 | `EC-` |
| `engine.md` | 戰鬥引擎 | `EG-` |
| `audio.md` | 音效 | `AU-` |

## 狀態

`待處理` → `進行中` → `待審核` → `已完成`（CEO 審核通過）
　　　　　　　　　　　　　　↘ `退回`（CEO 寫明原因）→ 負責角色修正後再改回 `待審核`

另有 `擱置`（等待其他任務或使用者決定）。

## 新增任務

- 寫在**目標角色**任務檔的「任務列表」最下方。
- ID = 前綴 + 三位流水號，接續該檔最後一號（例如 `LV-002`）。
- 寫完後在回覆中告訴使用者：「已在 `<檔名>` 新增 `<ID>`，請通知 <角色> 讀取。」

## 任務範本

```markdown
## [LV-001] 標題
- 狀態：待處理
- 優先度：高 / 中 / 低
- 來自：<角色>（日期）
- 依賴：<其他任務 ID，沒有就寫「無」>

**需求**
<具體要做什麼：檔案路徑、行號、預期結果>

**完成條件**
- <可驗證的條件>

### 回報（負責角色填寫）
- 修改檔案：
- 做了什麼：
- 如何驗證：
- 新增給其他角色的請求：
- 給 CEO 的注意事項：<commit 應包含哪些檔案、疑慮、建議、需要 CEO 更新的文件；沒有就寫「無」>

### 審核（CEO 填寫）
```

> ⚠️ CEO 審核時**只看任務檔**。任何你在對話中跟使用者說的重點，都必須同樣寫進回報，否則等於沒說。
